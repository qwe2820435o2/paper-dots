## 任务 2：真实富文本文章验证

背景：目前自家 WordPress 只有一篇默认的空白 `hello-world` 文章，
Gutenberg 样式覆盖（`src/app/blog.css`）虽然用外部真实站点（wptavern、
wordpress.org）验证过 `wp-block-button` / `heading` / `paragraph` /
`quote`，但**表格、代码块、对齐类（alignwide/alignfull）、特色图**这几项
只有 CSS，从未在自家环境用真实内容验证过。

### 步骤

1. 登录 WordPress 后台（`https://wordpress-dot.up.railway.app/wp-admin/`），
   新建一篇测试文章，标题可以是「Blog 样式测试」或类似，内容需要覆盖：
   - 至少一张插入的图片（建议同时测试一张普通尺寸图和一张设置为
     「宽版」或「全幅」对齐的图，对应 alignwide / alignfull）
   - 一个表格区块（几行几列，带表头）
   - 一段代码块（Gutenberg 的「代码」区块，不是行内代码）
   - 至少一段居中对齐和一段右对齐的文字（对应 has-text-align-center /
     has-text-align-right）
   - 一个引用块（quote）
   - 一个有序列表和一个无序列表
   - 一个按钮区块（wp-block-button）
   - 设置特色图片（Featured Image）
   - 正文中插入至少一处指向站内另一篇文章的内链（用编辑器的链接搜索
     功能选择已发布文章，不要手动输入 URL），用于顺带复验内链改写在真实
     后台操作下是否正常（此前的验证是用脚本模拟的数据，没有走过后台
     实际编辑器插入链接的路径）。
2. 发布文章（正式发布，不是仅保存草稿，因为 ISR 和内链映射表只处理
   已发布文章）。
3. 等待最多 60 秒（ISR revalidate 窗口），访问
   `dottypic.com/blog/[对应slug]`，对照检查：
   - 图片是否正常显示、宽版/全幅对齐的图片是否跳出了容器宽度限制
     （视觉上应比普通段落宽）
   - 表格样式是否整洁可读（边框、间距、表头是否有区分）
   - 代码块是否使用等宽字体、有没有背景色区分于正文
   - 对齐类是否生效
   - 引用块样式（缩进、边框或背景等视觉区分）
   - 列表缩进和项目符号/编号是否正常
   - 按钮样式是否融入站点视觉（圆角、颜色是否符合 lime 强调色系统）
   - 特色图是否在列表页卡片（`BlogPostCard`）和/或详情页顶部正确显示
   - 内链点击后是否跳转到 `dottypic.com/blog/...`（而不是
     `wordpress-dot.up.railway.app`），地址栏全程没有跳出主站域名
4. 如果发现某个区块样式不理想（例如表格太窄、代码块字体不对、按钮颜色
   不搭），记录下来，针对性修 `src/app/blog.css` 里对应的
   `.blog-scope` 规则即可，不需要大改。
5. 测试完成后，这篇测试文章可以保留作为长期的「样式基准文章」（方便
   以后改样式时有真实数据可参照），也可以事后删除或转为草稿——视团队
   习惯决定，不强制要求。

### 验收标准

上述检查项全部通过即可视为博客样式验证完成，可以正式对运营开放使用。
如果有条目效果不理想，先修复对应 CSS，再重新走一遍第 3 步的检查。
